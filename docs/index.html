RSA by hand

How your browser keeps secrets, worked out with small numbers you can check yourself. Code is on GitHub.

The idea, with a padlock

Suppose you want to send a friend a secret over the internet, where anyone can listen in, and you've never met to agree on a password. Here's how RSA solves that, without any math yet:

In RSA, the open padlock is the public key, the key is the private key, and snapping the lock shut is a bit of arithmetic that's easy to do and very hard to undo. The rest of this page builds a real (tiny) one.

One thing first: what "mod" means

RSA uses mod everywhere. a mod n is the remainder when you divide a by n. You already use it on clocks: 17 hours after midnight, the clock says 5, because 17 mod 12 = 5. Think of it as counting around a clock with n spots, starting at 0.

RSA does the same thing with huge numbers: the clock has n spots, where n is hundreds of digits long.

Step 1. Pick two primes

A prime is a number that only divides by 1 and itself, like 2, 3, 5, 7, 11, 13. We need two of them.

Real keys use primes around 300 digits long. These are small so the arithmetic fits on a page.

Step 2. Multiply them

Multiplying is easy. Going backwards (finding which two primes were multiplied) is hard when the numbers are huge. RSA is built on that difference.

n is public: it's part of the padlock. p and q stay secret.

Step 3. Compute φ(n)

A helper number that's easy to work out if you know p and q, and hard if you only know n.

φ(n) (say "phi of n") is Euler's totient: how many numbers from 1 to n share no factor with n. When n is two different primes multiplied together, it works out to (p − 1)(q − 1).

Step 4. Choose e

e is the number used for locking. The only rule: it can't share a factor with φ(n).

To check, find the greatest common divisor gcd(φ(n), e) with Euclid's algorithm, which is over 2,000 years old. Divide, keep the remainder, and repeat with the smaller pair until the remainder is 0:

Step 5. Find d

d is the number for unlocking. It's picked so that unlocking with d exactly undoes locking with e.

Precisely, e × d should leave remainder 1 when divided by φ(n). The extended Euclidean algorithm finds it: do the same divisions as in step 4, but also keep track of how to write each remainder using φ(n) and e.

Step 6. Lock (encrypt) a message

Turn each letter into a number, then scramble it with the public key. Anyone can do this part.

Each character becomes its ASCII code m (computers already store letters as numbers: "A" is 65), and the scrambled number is c = me mod n: multiply m by itself e times, then take the remainder.

Step 7. Unlock (decrypt) it

Do the same kind of scrambling, but with d instead of e, and the original numbers come back.

m = cd mod n. Only the person with d can do this.

Why unlocking works

A theorem from 1763 (Euler's) guarantees that locking with e and then unlocking with d always cancel out.

Show the proof

From step 5, e × d = 1 + k × φ(n) for some whole number k . So

cd = med = m1 + kφ(n) = m × (mφ(n))k ≡ m × 1k = m (mod n)

The step mφ(n) ≡ 1 (mod n) is Euler's theorem. It needs m and n to share no factor. RSA still works when they do, but proving that takes the Chinese Remainder Theorem.

Can someone break it?

Only by finding p and q from n. Try it: the button divides n by 2, 3, 5, 7, … until something goes in evenly.

Someone listening knows n = and e. If they find p and q, they can redo steps 3 to 5 and get d.

That's quick here. But the work grows with √n, so every extra digit of n makes it about 3 times slower. A real n has 617 digits, which means around 10308 tries. Faster factoring algorithms exist, but at that size they're still far too slow.

This is "textbook" RSA, the version taught in class. Real implementations add random padding before encrypting, so please don't use this to protect anything. The Python version works with real-size keys and also has signatures, faster decryption and some attacks.
