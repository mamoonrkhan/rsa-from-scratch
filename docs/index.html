RSA by hand

RSA is how your browser and a website agree on secrets over the internet. Underneath, it's nothing but the number theory from a discrete math class: primes, remainders, and Euclid's algorithm. This page walks through it with small numbers, so you can check every step yourself. Change anything in the boxes and the page updates.

1

Pick two primes

These are the secret ingredient. Real keys use primes over 300 digits long; we'll use small ones.

2

Multiply them

Everyone gets to see n. The security of RSA rests on one bet: given n, nobody can work out p and q in any reasonable time. Multiplying is easy; undoing it (factoring) is not.

3

Count the numbers that share no factor with n

This count is Euler's totient, φ(n). For a prime p, every number from 1 to p − 1 shares no factor with it, so φ(p) = p − 1. For two different primes multiplied together, φ(pq) = (p − 1)(q − 1). You can only compute this easily if you know p and q, which is why it stays secret.

4

Choose the public exponent e

6

Encrypt a message

Turn each character into a number (its ASCII code, m), then compute c = me mod n. Anyone can do this with the public key.

7

Decrypt it

Only the private key holder can do this: m = cd mod n.

8

Why does that give the message back?

Since e × d ≡ 1 (mod φ(n)), we can write e × d = 1 + k × φ(n) for some whole number k . Then

cd = med = m1 + kφ(n) = m × (mφ(n))k ≡ m × 1k = m (mod n)

The step where mφ(n) ≡ 1 is Euler's theorem. It holds whenever m shares no factor with n; with a bit more work (using the Chinese Remainder Theorem) you can show RSA still works when it does.

9

Now try to break it

An attacker sees n = and e. If they can factor n, they can redo steps 3 to 5 and get d. The simplest way is to try dividing by 2, 3, 5, 7, … until something works.

With these tiny primes that's instant. The number of tries grows like √n, so every extra digit in n makes it about 3 times slower. A real 617-digit n would take around 10308 tries: far more than the number of atoms in the universe (about 1080). Better factoring methods exist, but none are fast enough, and that gap is what keeps your data safe.
